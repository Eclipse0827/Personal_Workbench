# 缓一缓 · 个人学术工作台

> 安排学习任务、管理长期计划；用一个能关联待办的番茄钟留出专注时间；
> 把 PDF 教材拆成章、节，逐节读讲义、看原文、向 AI 提问。
> 思绪混乱或卡住的时候可以自然地聊一聊，等你确认之后，再把有用的部分变成待办。

对应需求文档：`创意二稿`（V1.0 PRD）。

## 怎么跑起来

**最简单**：双击 `start.bat`，浏览器会自动打开。

**命令行**：

```bash
node server/server.js --open      # 启动并自动打开浏览器
node server/server.js             # 只启动 → http://127.0.0.1:5180
node server/server.js --port 8080 # 换端口
```

不需要 `npm install`，也没有构建步骤。只需要 Node.js 18+。
按 `Ctrl + C` 停止。

### 桌面浮窗（可选，需要 Electron）

待办页或专注页右上角的「浮到桌面」，会在桌面上开一个**透明、无边框、置顶、不占任务栏**的小窗。
小窗里可以：

- 直接勾选未完成待办；
- 在输入框里敲一件新待办，按回车或点「添加」；
- 对某条待办开始 25 分钟专注，或选 15 / 25 / 45 分钟自由专注；
- 暂停 / 继续、结束并记下、放弃这一轮；
- 和网页版**共享同一轮计时**：在哪边暂停、结束，另一边都会同步。

第一次使用需要装一次 Electron（约 100MB）：

```bash
npm install --save-dev electron
```

然后在页面上点「浮到桌面」，或者用命令行：

```bash
npm run float                         # 没开服务会自动起一个
npm run float -- --port=5180          # 指定端口
node desktop/launch.js --url=http://127.0.0.1:5180
```

Electron 的安装包在海外，下载慢时可以换国内镜像：

```bash
ELECTRON_MIRROR=https://cdn.npmmirror.com/binaries/electron/ npm install --save-dev electron
```

不装 Electron 时网页版完全不受影响；点「浮到桌面」会明确告诉你还差哪一步。
浮窗只连 `127.0.0.1` 上的本地服务，不联网、不上传数据。

### 三个 AI 引擎

在「设置与数据」里切换。三条路各自的责任边界很明确：

| 引擎 | 联网 | 谁生成回复 | 谁生成梳理卡和行动方案 |
|---|---|---|---|
| **本地规则引擎**（默认） | 否 | 本地规则 | 本地规则 |
| **Ollama 本地模型** | 只连本机 11434 | 本机模型 | 本地规则 |
| **远程模型** | 是 | 远程模型 | 远程模型 |

**为什么 Ollama 模式只让模型管「说话」**：实测本机 `deepseek-r1:1.5b` 在 `format:json` 下会把
键名写错（`"needQuestion:"`），输出也会被截断；更要紧的是它不遵守 PRD 的硬规则。
所以结构化内容一律由规则引擎生成，模型只负责把一句话说得更自然。
这样「专业课还没定就不排任务」这类规则，换任何模型都不会被破坏。

**护栏与小模型**：模型输出如果出现第三人称（「用户」）、复述背景、长篇泛泛建议、
客服腔或回显输入，就会被判定为不合格，**自动退回规则引擎的原话**，并在消息上如实标注
「规则引擎」。参数量小于 3B 的模型，界面上会给出一次性提示。

**教材精读的数据边界**：章节框架始终由本地规则根据 PDF 书签 / 目录页 / 正文标题整理，
不交给模型编目录。每一节的讲义和问答只在这一节被打开时才生成：本地规则引擎不联网；
本机 Ollama 只连本机；选远程模型时，这一节的相关原文会发送到设置里的接口，界面会提前说明。
每条讲义和回答都标着实际使用的引擎，不会把规则整理说成「AI 讲解」。

扫描版教材的 OCR 也在本机完成（Windows 自带的 OCR），不联网、不上传 PDF。
讲义和问答的生成是一个可替换的引擎接口：现在接的是本地规则 / Ollama / 远程模型，
以后把某一节原文交给外部 agent 平台或更强的多模态模型处理，也只需要换这一层，
不需要重做导入、章节、进度和阅读界面。

需要提问的关键问题（「你现在主要准备哪几科」）由规则引擎附在模型回复之后，
不会被小模型吃掉 —— 这是刻意设计的，提问权不交给模型。

> 想换更大的模型：`ollama pull qwen2.5:7b`，然后到设置页点「重新检测」。
> 本次开发环境访问不到 `registry.ollama.ai`，所以没能替你拉取。

### 本机装哪个模型（按费用优先）

全部免费 —— 本地模型只花磁盘和电，没有订阅费。所以选型只看「能不能在你的机器上跑得动」。

这台机器：16 线程、16GB 可用内存、没有独立显卡（纯 CPU 推理）。

| 模型 | 大小 | 建议 | 说明 |
|---|---|---|---|
| **qwen2.5:7b** | ~4.7GB | **首选** | 中文理解明显好过 3B，CPU 上大约 4–7 tok/s；我们每条回复只要几十字，够用 |
| qwen2.5:3b | ~1.9GB | 想更快选这个 | 质量比 7B 差一档，但比 1.5B 好很多 |
| qwen2.5:1.5b | ~1GB | 不推荐 | 就是现在这个档位附近的能力，措辞经常不合格 |
| deepseek-r1 系列 | 各异 | 不适合这个场景 | 它先写一大段推理再回答，慢且容易把正文截断 |
| llama3.2:3b | ~2GB | 备选 | 中文不如 qwen 系列 |

```bash
ollama pull qwen2.5:7b
```

前提是网络能连到 `registry.ollama.ai`。拉完之后回设置页点「重新检测」，下拉里就会出现它。

模型变大之后可以做的一件事：现在是「规则引擎定结构、模型只改措辞」，
换成 7B 以后可以放开一点，让模型直接产出梳理内容（护栏仍然保留）。
这一步等你装好模型我再调。

### 如果提示端口被占用

不会失败的。不指定端口时，5180 被占会自动顺延到 5181、5182……（最多试 10 个），
并在启动时明确告诉你换到了哪个端口。控制台打印的那个地址就是要打开的那个。

只有你**显式**用 `--port` 指定端口时才是严格模式：被占用就如实报错，不会偷偷换 ——
这样自动化测试才能确定地拿到自己要求的端口。

### 如果双击 `start.bat` 报「不是内部或外部命令」

那是**批处理文件编码**的问题，已经修好了。记一下原因，免得以后改坏：

`cmd.exe` 解析 `.bat` 时用的是**系统 ANSI 代码页**（中文 Windows 是 936/GBK），
不是 UTF-8。所以一个存成 UTF-8、里面带中文的 `.bat`，会被读成一堆乱码字节，
`echo` 出去的文字就变成了「不是内部或外部命令」。

现在 `start.bat` 有两条硬约束：

1. **纯 ASCII**，一个非 ASCII 字节都没有 —— 启动提示是英文的，中文全部由 Node 打印；
2. **CRLF 换行** —— LF 的批处理在 `goto` 标签上会出问题。

脚本里先执行 `chcp 65001`，把控制台切成 UTF-8，所以 Node 输出的中文（应用横幅、
报错、地址）都能正常显示。**想改这个文件的话，请保持纯 ASCII + CRLF。**

> **关于技术路线**：PRD 里写的初步路线是 Vue 3 + Vite。
> 实际检查的结果是：本机 `npm registry` 不可达，装不了依赖。
> 而 PRD 阶段 0 明确要求「如果现有项目已经有可用的技术结构，应优先复用，不得未经检查直接重建项目」，
> 所以这里沿用了现有的零依赖结构（Node 内置模块 + 原生 ES 模块），没有推倒重来。
> 分层做了严格切分（见下方「代码结构」），将来要换成 Vue 或换成后端 API，改的是数据访问层和视图层，不是业务逻辑。

| 页面 | 地址 | 做什么 |
|---|---|---|
| **工作台** | `#/` | 欢迎区、今日计划、AI 快速入口、最近计划、工具入口 |

| **专注番茄钟** | `#/focus` | 关联待办或自由专注；按天看内容饼图与累计时长；计时不因刷新丢失，结束后可自动勾选待办并撤销；可浮到桌面 |
| **教材精读** | `#/textbooks` | 导入 PDF、管理书架；进入 `#/textbook/:id` 后按章、节阅读 |
| **AI 整理空间** | `#/chat` | 自然对话 → 问题梳理卡 → 行动方案卡 → 确认创建任务 |
| **我的档案** | `#/archive` | 你主动保存的思考档案、摘要、学习计划 |
| **我的工具** | `#/tools` | 已实现的工具 + 明确标注「规划中」的工具 |

设置与数据在侧栏底部，与「核心工作 / 我的」分组分开，不挤占每天的入口。
专注计时进行中时，离开专注页会在右下角留一个迷你计时器，可以随时暂停或回到专注页。

**桌面浮窗**是另一条入口：透明小窗里同时放着待办和当前计时。它和网页版不是两套状态，
服务端只保存一份「正在进行的这一轮」（`data/focus-active.json`），两边每 2.5 秒对一次。
网页端断网时仍会本地计时，恢复后补交；浮窗里放弃的计时会留下取消标记，网页端不会把它接回来。

## 核心流程

**手动管理任务（不需要 AI）**

工作台或待办页 → 新增任务（只需标题）→ 可选填日期、计划、优先级 → 保存 → 出现在今日计划 / 未完成列表。

**专注番茄钟**

选一条未完成待办（或写一句自由专注的目标）→ 设时长 → 开始 → 计时在浏览器里走，刷新、切页面都不会丢 →
结束（或提前结束）时记录实际专注时长；如果关联了待办且勾选了自动完成，就把那条待办勾成已完成 →
结果卡和专注历史里都能撤销这次自动勾选。提前结束按实际经过的时间记录，不会按计划时长虚记。

专注页按**本地日历日**汇总，不按「最近 24 小时」切：昨天 15 分钟的背单词，今天打开仍然看得见。
当天有多种专注内容时，饼图按内容拆分时间；点某一项，可以看这件事从开始到现在一共花了多久，
下面的专注记录也会跟着筛选。跨过午夜的一轮按结束时间归入当天。

**教材精读**

导入 PDF → PDF.js 在浏览器里提取文字，并优先读取 PDF 书签；没有书签就尝试目录页和正文标题，
都没有就按页分段并如实说明来源 → 打开某一节时，才生成这一节的讲义（本地规则 / 本机模型 / 远程模型）→
在「讲义 / 教材原文 / PDF 原页」之间切换对照 → 随时向 AI 提这一节的问题 → 标记已读，书架记录进度。

全书导览里有三层内容：一张可点击的**全书脉络图**（章 → 节，点章节或小节直接进入，有 PDF 时附页码链接）、
一份导览文字，以及从书名、章节标题和可读正文里挑出的**术语卡**。术语卡用大白话解释，
并配一个生活里的例子；没有把握的词宁可不放，也不自动编造。

讲义以文字为主。只有标题或正文与欧姆定律、分组交换、TCP 三次握手**强相关**的节，才会在这一节末尾
折叠一个「辅助理解 · 可选」动画，默认不加载；弱相关不挂动画，同一章里靠正文兜底命中的同一个动画也不会反复出现。

**扫描版教材**

没有文字层、或文字层是乱码时，服务端会用 Windows 自带的 OCR 在本机识别，优先读前几页的目录，
再按小节懒加载正文。需要系统安装中文 OCR 语言包（设置 → 时间和语言 → 语言和区域 → 中文 →
语言选项 → 可选功能里添加「光学字符识别」）。OCR 结果会标成「本机 Windows OCR」，
公式、符号和分栏可能失真；识别不出的页面会被排除在讲义依据之外，不会拿乱码硬凑解释。
目录识别也会挑错：习题页、答案页即使有编号和数字列，也不会被当成目录；认不出目录时退回按页分段，
并在导览下方如实写明来源。

**AI 辅助拆解**

工作台或 AI 整理空间输入 → AI 回应并给出可编辑的梳理卡 →（必要时问一个关键问题）→ 给出行动方案 →
你修改、勾选其中几条 → 确认创建 → 才真正进入待办。

## PRD 里几条最容易做歪的约束，是怎么落地的

**1. AI 建议 ≠ 正式任务。**
建议行动存在 `conversation.proposals[].actions[]` 里，只有 `POST .../confirm` 才创建 `Task`。
未确认前，待办列表里查不到它们 —— 自测里有专门的断言。

**2. 重复确认不会重复创建。**
每条建议行动有稳定 `id`；创建后写入 `createdTaskId`。
再次确认时：先看 `createdTaskId` 指向的任务还在不在，再用「同方案 + 同标题」兜一层，
两层都命中就跳过并如实告诉你「这一条已经创建过了」。

**3. 只针对用户已经确定的科目规划。**
「专业课还没定」里提到了专业课，但它不是已确定的科目。
`extractSlots()` 按分句判断否定语境，把「已确定」和「还没定」分开：
已确定的才生成任务，还没定的只进方案的 `pendingItems`（界面上叫「还没确定，所以先不安排」）。

**4. 不重复问同一个问题，且记得自己在上一轮问了什么。**
`conversation.asked` 记录问过的话题，`conversation.pendingIntent` 记住「正在等用户回答」。
所以用户只回一句「数学一和英语一」时，AI 不会把它当成新的闲聊，而是接着上一轮的规划意图走。

**5. 只想倾诉时不强行给计划。**
意图是「倾诉」时直接不生成 proposal，只回应，并留一句「想拆成小任务就跟我说」。

**6. 模拟引擎绝不冒充真实模型。**
每条 AI 消息都带 `provider: 'mock' | 'real'`，界面上分别显示「模拟引擎」或「真实模型」标签。
默认是 mock，不联网。设置页明确写了切到真实模型后你的话会被发送到那个服务。

**7. 原始记录和 AI 整理分开。**
档案的 `content` 是用户保存的摘要，`sourceConversationId` 只是指回来源。
改摘要不会动对话，删对话也不会动档案（反之亦然）。

**8. 未实现的功能不装成能用。**
教材精读已经接到真实页面；但独立的「章节关系图」「习题生成」「错题整理」仍标着「规划中」，
点了只会告诉你还没做，不会跳到一个空壳页面。扫描版 PDF 已支持本机 OCR，但会明确标注哪些文字来自 OCR、
哪些页面没有识别出来，不会把 OCR 结果冒充成原文。

**9. 番茄钟只在真正结束时留下记录，统计不因重开页面清零。**
放弃的一轮不写记录、不动待办；自动勾选发生在服务端，并记下任务原来的状态，
撤销时按原状态还原。结束请求带客户端令牌，断网重试不会记成两次。
每天的时长和内容拆分由服务端按本地日历日聚合，数据在 `data/focus-sessions/`，
刷新、关浏览器、隔天再打开都还在；界面不显示连续打卡和排名。

**10. PDF 原文不整本外传。**
文字提取在浏览器里完成，扫描版 OCR 在本机完成；章节框架由本地规则整理；
只有打开某一节时，才把这一节的相关文字送给所选的引擎。远程模型的数据流向在导入页、设置页和
每一节的引擎标记里都写清楚了。

## 第一版数据是怎么处理的

第一版（焦虑记录 → 思考档案 → 回看）里你已经写下的记录，**一条都没有丢**：

- `data/entries/` 里的原始文件**保持原样，只读，从不修改**
- 启动时自动迁移成「我的档案」里的 `thought` 档案，用 `legacyEntryId` 指回原记录
- 迁移正文里把「原始记录」和「当时整理的内容」分开，标得清清楚楚

**迁移是逐条自愈的**，不是「跑过一次就永久跳过」：

| 情况 | 行为 |
|---|---|
| 原始记录在、档案没了 | 重新补一份 |
| 档案还在 | 跳过 |
| 你在界面上主动删过这份档案 | 记进 `meta.dismissedLegacyIds`，不再复活 |

这个改动是踩出来的：早先只在 `meta.json` 记一个「已迁移」标记，结果迁移出来的档案
一旦被删掉（哪怕是测试脚本清理出错），原始记录还在却再也回不到档案里。
现在补回来过，并且不会再因为误删永久丢失。

### 教材数据的两次就地升级

已有的教材不需要重新导入。启动时会各跑一次，标记记在 `data/meta.json`：

| 迁移 | 做什么 | 为什么 |
|---|---|---|
| `textbook-demos-v2` | 按新规则重算每一节的动画；标题强匹配优先，正文兜底要多个明确信号，同章弱匹配去重 | 旧逻辑按章标题匹配，导致一本书里几乎每节都挂着同一个动画 |
| `textbook-lessons-text-first-v1` | 本地规则讲义重新生成；远程模型讲义去掉「先看动画」这类建议 | 动画只辅助理解，讲义必须以文字和原文为主 |

原文、页数、章节框架、已读进度和问答都不动；这两次迁移只更新动画标记与讲义正文。

旧的那套「思考习惯自动归纳」是**故意没有搬过来**的：
PRD 2.5 明确写了「V1.0 不自动生成未经用户确认的个人心理画像」，
原来那一页会自动生成画像，与这条冲突，所以按新文档删掉了。

## 视觉方向

参考「暖白纸感 + 深祖母绿」的安静风格重做过一版：

- **全站宋体**（`Songti SC` / `SimSun` / `宋体`，西文回落到衬线）。宋体字形比黑体小一号，
  所以正文放大到 15.5px、行距放宽到 1.85，读起来才不费劲
- 底色是偏暖的纸白（`#f1f0ea`），卡片纯白、大圆角、阴影极淡，几乎不用边框
- 主色是深祖母绿，只用在强调处；暖橙只出现在「剩余 / 提醒」这类数字上
- 侧栏用白色胶囊表示当前页，底部有一条任务完成度进度
- 页面标题厚重，说明行小字拉开字距；大数字用等宽数字
- 「今日」卡做成一卡三栏、竖分隔线，正对应参考图的版式

PRD 7.1 的约束没有丢：低饱和自然色、不用制造压力的红色警告、没有排行榜和连续打卡。
换来的是一套安静但不死板的界面 —— 欢迎区不含任何催促文案这一点，自测里有断言守着。

## AI 整理空间为什么不「像填表」

第一版做成「输入一句 → 吐一张镶边的卡」，反馈是：不像聊天、不舒缓、太模板。
这一版按下面几条改的：

- **AI 的话不带气泡、不带边框** —— 就是一段话。一段一个气泡，
  一段回复会被拆成几条，读起来像连着说了几句
- **「问题梳理」收起来** —— 变成一个可以点开的小标题，只有你点开才展开；
  里面每条仍然能直接改、能删
- **「建议」长在对话里** —— 一行一句，没有底色没有框，label 写的是
  「我建议可以试试这几步」，不再是「方案卡」
- **不用下指令** —— 不需要说「帮我拆成小任务」。只要这一轮聊到了能落地的事，
  AI 会直接说「我建议你可以先从很小的一步开始：…」，然后由你确认
- **每条回复后面有快捷回话** —— 「好，加进待办」「只想先做第一条」「这次先不用」，
  让对话能接下去，而不是问一句就断了
- **输入框 Enter 发送、Shift+Enter 换行**，正在输入显示三个跳动的点
- **先接住情绪再谈事情** —— 回复的第一段永远是承接，第二段才说事

产品约束照旧：梳理内容只呈现真正需要的栏目；建议必须你确认才创建任务；
可只选部分；重复确认不重复创建；只想倾诉时不推计划。

## 数据在哪

```
data/
  tasks/            任务，一个任务一个 JSON 文件
  plans/            学习计划
  conversations/    对话、消息、行动方案（都在一个文件里）
  archives/         我的档案
  entries/          第一版的原始记录（只读保留）
  focus-sessions/   已完成的专注记录（含实际秒数、是否自动勾选；按本地日历日聚合展示）
  focus-active.json 正在进行的那一轮（网页与桌面浮窗共用；结束后删除）
  textbooks/        教材元数据、章节框架、讲义、问答、提取的逐页文字与原始 PDF
  settings.json     AI 引擎设置（含 API Key，注意别外传）
  meta.json         迁移标记
  .float-runtime/   浮窗的窗口位置与 Electron 缓存（可随时删，删了只是位置回到默认）
```

写入用的是「临时文件 + 改名」的原子替换，写到一半出错不会把已有记录写坏。
单个 JSON 文件损坏也只会被跳过，不会让整站打不开。

**备份**：设置页可以导出
- `导出任务、对话与档案（JSON）` — 这几类数据的完整备份，**不含 API Key**
- `导出任务、对话与档案（Markdown）` — 人能直接读，含计划、任务、档案、完整对话

专注记录和教材数据目前**不在**这两个导出文件里；需要完整备份时，请一并复制
`data/focus-sessions/` 和 `data/textbooks/`。设置页也写了这句话，避免把部分备份误当成「全部」。

## 自测

```bash
node server/selftest.js    # 接口，218 项，对照 PRD 第八章验收标准
node server/uitest.js      # 前端视图渲染，171 项
```

`selftest.js` 真实跑完整流程，重点验证：无日期任务不消失、删计划不删任务、
未确认建议不进待办、只创建选中的部分、重复确认不重复创建、放弃不产生任务、
改摘要不影响对话、Key 不回显也不进导出、原有档案一份不少；番茄钟的自动勾选 /
幂等提交 / 撤销还原，昨天的专注仍能按天、按内容统计；**浮窗与网页共用的进行中计时**
（开始 / 暂停后剩余时间不走 / 继续 / 提前结束 / 到点自动结束 / 放弃后留取消标记）；
教材的书签框架、动画严格匹配与
旧书重算、逐节讲义、问答与已读进度；乱码检测与本机 OCR 的来源标记；OCR 目录解析能
排除习题 / 答案页；重复页眉页脚不会带进讲义；中文编号与分点题目的换行。
它只删除自己创建的数据。

如果测试开始时你正开着一轮专注，共用计时那一组会自动跳过，不会打断或覆盖它。
进行中的计时文件在测试结束后按原样恢复。

设置相关的断言会先备份 `data/settings.json`，结束时原样恢复（包括 API Key），
不会为了测试把你的真实配置清掉。

`uitest.js` 用一个最小 DOM 桩在 Node 里把 12 个视图真正渲染一遍，
能抓到拼错的属性、未定义函数、渲染时才炸的表达式、对象被塞进 DOM 变成 `[object Object]`。
它还会静态检查浮窗页面：独立于主站外壳、能勾待办与暂停/放弃、不使用 `innerHTML`、
桌面外壳透明置顶且隔离 Node。它不保证 CSS 的实际观感 —— 那需要真人打开看。

Ollama 相关的行为不进自动化（它会真调本机模型、耗时不确定），
所以是手动验证的：`/api/ai/status` 探测、模型列表、切换引擎、回复里的引擎标注与回退。

> ⚠️ **自测会写入并清理测试数据。** 它只删除自己创建的东西（启动时记录快照，结束时对比），
> 但如果你**同时在用这个应用新建任务**，理论上可能撞上竞态。
> 所以建议在不用的时候跑，或者先导出一份备份。
> 你真实的数据（任务、计划、对话、档案）在正常使用中不会被自测碰到。
