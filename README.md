# 缓一缓 · 个人学术工作台

> 安排学习任务、管理长期计划；用一个能关联待办的番茄钟留出专注时间；
> 把 PDF 教材拆成章、节，逐节读讲义、看原文、向 AI 提问。
> 思绪混乱或卡住的时候可以自然地聊一聊，等你确认之后，再把有用的部分变成待办。

对应需求文档：`创意二稿`（V1.0 PRD）。

---

## 怎么跑起来

**最简单**：双击 `start.bat`，浏览器会自动打开。

**命令行**：

```bash
node server/server.js --open      # 启动并自动打开浏览器
node server/server.js             # 只启动 → http://127.0.0.1:5180
node server/server.js --port 8080 # 换端口
```

不需要 `npm install`，也没有构建步骤。只需要 Node.js 18+。
按 `Ctrl + C` 停止。

### 桌面浮窗（可选，需要 Electron）

待办页或专注页右上角的「浮到桌面」，会在桌面上开一个**透明、无边框、置顶、不占任务栏**的小窗。
小窗里可以：

- 直接勾选未完成待办；
- 在输入框里敲一件新待办，按回车或点「添加」；
- 每条待办可以单独设专注时长（15 / 25 / 45 分钟，或输入 1–180 分钟），下次打开还记得；
- 暂停 / 继续、结束并记下、放弃这一轮；
- 和网页版**共享同一轮计时**：在哪边暂停、结束，另一边都会同步；
- 点顶部「吸」开启吸边：窗口吸附屏幕左右边并收成一颗桌面悬浮球，专注进行中球上直接显示倒计时；
  点球展开浮窗，按住球可以拖动，松手重新吸边；展开后点底部「吸边中 · 取消」可关闭吸边。

第一次使用需要装一次 Electron（约 100MB）：

```bash
npm install --save-dev electron
```

然后在页面上点「浮到桌面」，或者用命令行：

```bash
npm run float                         # 没开服务会自动起一个
npm run float -- --port=5180          # 指定端口
node desktop/launch.js --url=http://127.0.0.1:5180
```

Electron 的安装包在海外，下载慢时可以换国内镜像：

```bash
ELECTRON_MIRROR=https://cdn.npmmirror.com/binaries/electron/ npm install --save-dev electron
```

不装 Electron 时网页版完全不受影响；点「浮到桌面」会明确告诉你还差哪一步。
浮窗只连 `127.0.0.1` 上的本地服务，不联网、不上传数据。
吸边偏好会记住：下次启动如果还开着吸边，会直接以悬浮球出现在上次的位置。

### 三个 AI 引擎

在「设置与数据」里切换。三条路各自的责任边界很明确：

| 引擎 | 联网 | 谁生成回复 | 谁生成梳理卡和行动方案 |
|---|---|---|---|
| **本地规则引擎**（默认） | 否 | 本地规则 | 本地规则 |
| **Ollama 本地模型** | 只连本机 11434 | 本机模型 | 本地规则 |
| **远程模型** | 是 | 远程模型 | 远程模型 |

**为什么 Ollama 模式只让模型管「说话」**：实测本机 `deepseek-r1:1.5b` 在 `format:json` 下会把
键名写错（`"needQuestion:"`），输出也会被截断；更要紧的是它不遵守 PRD 的硬规则。
所以结构化内容一律由规则引擎生成，模型只负责把一句话说得更自然。
这样「专业课还没定就不排任务」这类规则，换任何模型都不会被破坏。

**护栏与小模型**：模型输出如果出现第三人称（「用户」）、复述背景、长篇泛泛建议、
客服腔或回显输入，就会被判定为不合格，**自动退回规则引擎的原话**，并在消息上如实标注
「规则引擎」。参数量小于 3B 的模型，界面上会给出一次性提示。

**教材精读的数据边界**：章节框架和本章知识地图始终由本地规则根据 PDF 书签 / 目录页 / 正文标题整理，
不交给模型编目录。每一节的讲义、问答和图解只在这一节被打开或被提问时才生成：本地规则引擎不联网；
本机 Ollama 只连本机；选远程模型时，这一节的相关原文和问题会发送到设置里的接口，界面会提前说明。
每条讲义、回答和图解都标着实际使用的引擎，不会把规则整理说成「AI 讲解」。

扫描版教材的 OCR 也在本机完成（Windows 自带的 OCR），不联网、不上传 PDF。
讲义和问答的生成是一个可替换的引擎接口：现在接的是本地规则 / Ollama / 远程模型，
以后把某一节原文交给外部 agent 平台或更强的多模态模型处理，也只需要换这一层，
不需要重做导入、章节、进度和阅读界面。

需要提问的关键问题（「你现在主要准备哪几科」）由规则引擎附在模型回复之后，
不会被小模型吃掉 —— 这是刻意设计的，提问权不交给模型。

> 想换更大的模型：`ollama pull qwen2.5:7b`，然后到设置页点「重新检测」。
> 本次开发环境访问不到 `registry.ollama.ai`，所以没能替你拉取。

### 本机装哪个模型（按费用优先）

全部免费 —— 本地模型只花磁盘和电，没有订阅费。所以选型只看「能不能在你的机器上跑得动」。

这台机器：16 线程、16GB 可用内存、没有独立显卡（纯 CPU 推理）。

| 模型 | 大小 | 建议 | 说明 |
|---|---|---|---|
| **qwen2.5:7b** | ~4.7GB | **首选** | 中文理解明显好过 3B，CPU 上大约 4–7 tok/s；我们每条回复只要几十字，够用 |
| qwen2.5:3b | ~1.9GB | 想更快选这个 | 质量比 7B 差一档，但比 1.5B 好很多 |
| qwen2.5:1.5b | ~1GB | 不推荐 | 就是现在这个档位附近的能力，措辞经常不合格 |
| deepseek-r1 系列 | 各异 | 不适合这个场景 | 它先写一大段推理再回答，慢且容易把正文截断 |
| llama3.2:3b | ~2GB | 备选 | 中文不如 qwen 系列 |

```bash
ollama pull qwen2.5:7b
```

前提是网络能连到 `registry.ollama.ai`。拉完之后回设置页点「重新检测」，下拉里就会出现它。

模型变大之后可以做的一件事：现在是「规则引擎定结构、模型只改措辞」，
换成 7B 以后可以放开一点，让模型直接产出梳理内容（护栏仍然保留）。
这一步等你装好模型我再调。

### 如果提示端口被占用

不会失败的。不指定端口时，5180 被占会自动顺延到 5181、5182……（最多试 10 个），
并在启动时明确告诉你换到了哪个端口。控制台打印的那个地址就是要打开的那个。

只有你**显式**用 `--port` 指定端口时才是严格模式：被占用就如实报错，不会偷偷换 ——
这样自动化测试才能确定地拿到自己要求的端口。

### 如果双击 `start.bat` 报「不是内部或外部命令」

那是**批处理文件编码**的问题，已经修好了。记一下原因，免得以后改坏：

`cmd.exe` 解析 `.bat` 时用的是**系统 ANSI 代码页**（中文 Windows 是 936/GBK），
不是 UTF-8。所以一个存成 UTF-8、里面带中文的 `.bat`，会被读成一堆乱码字节，
`echo` 出去的文字就变成了「不是内部或外部命令」。

现在 `start.bat` 有两条硬约束：

1. **纯 ASCII**，一个非 ASCII 字节都没有 —— 启动提示是英文的，中文全部由 Node 打印；
2. **CRLF 换行** —— LF 的批处理在 `goto` 标签上会出问题。

脚本里先执行 `chcp 65001`，把控制台切成 UTF-8，所以 Node 输出的中文（应用横幅、
报错、地址）都能正常显示。**想改这个文件的话，请保持纯 ASCII + CRLF。**

> **关于技术路线**：PRD 里写的初步路线是 Vue 3 + Vite。
> 实际检查的结果是：本机 `npm registry` 不可达，装不了依赖。
> 而 PRD 阶段 0 明确要求「如果现有项目已经有可用的技术结构，应优先复用，不得未经检查直接重建项目」，
> 所以这里沿用了现有的零依赖结构（Node 内置模块 + 原生 ES 模块），没有推倒重来。
> 分层做了严格切分（见下方「代码结构」），将来要换成 Vue 或换成后端 API，改的是数据访问层和视图层，不是业务逻辑。

## 主要页面

| 页面 | 地址 | 做什么 |
|---|---|---|
| **工作台** | `#/` | 欢迎区、今日计划、和 AI 聊会入口、最近计划 |
| **待办与计划** | `#/tasks` | 完整的任务与计划管理中心，**不依赖 AI 也能用** |
| **专注番茄钟** | `#/focus` | 关联待办或自由专注；按天看内容饼图与累计时长；计时不因刷新丢失，结束后可自动勾选待办并撤销；可浮到桌面 |
| **学习项目** | `#/projects` | 把课程放进项目，记录最近学习集数与完成进度；进入 `#/projects/:id` 管理课程、继续学习、完成本集 |
| **教材精读** | `#/textbooks` | 导入 PDF、管理教材目录；进入 `#/textbook/:id` 后按章、节阅读 |
| **外刊阅读** | `#/articles` | 粘贴 / 导入外刊文章，管理书架与生词本；进入 `#/article/:id` 阅读、查词、高亮批注、导入选择题，并就这一篇提问 |
| **AI 整理空间** | `#/chat` | 自然对话 → 问题梳理卡 → 行动方案卡 → 确认创建任务 |

学习工具直接列在左侧栏的「学习工具」分组里，目前是已经能用的学习项目、教材精读与外刊阅读；
不再放置章节知识框架、习题生成、错题整理这类尚未实现的入口。

「我的档案」暂时从界面收起：`data/archives/`、导出接口和 `/api/archives` 都原样保留，
已有档案一条没删，以后想恢复界面时数据还在。

学习项目的「继续学习 / 完成本集」都由接口计算并写回集数：前端只负责打开接口返回的地址，
不会自行把「最近学习集数」加一。删除项目会删掉项目下的课程，但关联的待办只解除项目和课程关联，
任务本身不会被删除。

设置与数据在侧栏底部，与「核心工作 / 学习工具」分组分开，不挤占每天的入口。
专注计时进行中时，离开专注页会在右下角留一个迷你计时器，可以随时暂停或回到专注页。

**桌面浮窗**是另一条入口：透明小窗里同时放着待办和当前计时。它和网页版不是两套状态，
服务端只保存一份「正在进行的这一轮」（`data/focus-active.json`），两边每 2.5 秒对一次。
网页端断网时仍会本地计时，恢复后补交；浮窗里放弃的计时会留下取消标记，网页端不会把它接回来。

## 核心流程

**手动管理任务（不需要 AI）**

工作台或待办页 → 新增任务（只需标题）→ 可选填日期、计划、优先级 → 保存 → 出现在今日计划 / 未完成列表。

**学习项目**

新建项目 → 在项目里添加课程（平台、来源、链接、总集数、已完成集数、最近学习集数）→
点「继续学习」打开接口算出的目标集数，并记录最近学习时间 → 学完当前集后点「完成本集」，
已完成集数只在按顺序完成时推进；跳集需要先手动调整进度。项目整体进度按所有填写了总集数的课程加权计算，
没填总集数的课程不参与，也不会被说成「已完成」。

**专注番茄钟**

选一条未完成待办（或写一句自由专注的目标）→ 设时长 → 开始 → 计时在浏览器里走，刷新、切页面都不会丢 →
结束（或提前结束）时记录实际专注时长；如果关联了待办且勾选了自动完成，就把那条待办勾成已完成 →
结果卡和专注历史里都能撤销这次自动勾选。提前结束按实际经过的时间记录，不会按计划时长虚记。

专注页按**本地日历日**汇总，不按「最近 24 小时」切：昨天 15 分钟的背单词，今天打开仍然看得见。
当天有多种专注内容时，饼图按内容拆分时间；点某一项，可以看这件事从开始到现在一共花了多久，
下面的专注记录也会跟着筛选。跨过午夜的一轮按结束时间归入当天。

同一件事写成「单词 / 墨墨背单词 / 背单词」时，在时长汇总里选中其中一项，用「把这一项归到」
选择一条待办或另一项专注内容，几行时长就会合并成一行，饼图和记录一起按合并后的名字统计。
归类只记一条对应关系，**不改写、不删除原始专注记录**；历史里仍会标出「原「…」」。
合并随时可以撤销，撤销后各项恢复独立统计。归类关系存在 `data/focus-aliases.json`。

**教材精读**

导入 PDF → PDF.js 在浏览器里提取文字，并优先读取 PDF 书签；没有书签就尝试目录页和正文标题，
都没有就按页分段并如实说明来源 → 打开某一节时，才生成这一节的讲义（本地规则 / 本机模型 / 远程模型）→
在「讲义 / 教材原文 / PDF 原页」之间切换对照 → 随时向 AI 提这一节的问题 → 标记已读，书架记录进度。
打开一本书后进入沉浸阅读：全局侧栏和移动端顶栏收起，整屏留给这本书，只保留书自己的目录与「我的书架」入口。

全书导览页只保留两块内容：一张可点击的**全书脉络图**（章 → 节，点章节或小节直接进入，有 PDF 时附页码链接），
以及从书名、章节标题和可读正文里挑出的**术语卡**。术语卡用大白话解释，
并配一个生活里的例子；没有把握的词宁可不放，也不自动编造。

进入某一节后，最上方先放一张**本章知识地图**：本章各节排成分支，每节带 2–3 个从原文抽出的要点，
点任意节点可直接跳到那一节。地图由本地规则整理并明确标注，不是模型生成；它只负责建立章节顺序感，
具体讲解仍在下面的讲义里。

讲义按「位置 → 脉络 → 要点」展开：先用一句话说明这一节接在上一节之后要解决什么问题，
再用编号步骤（`thread`）把「问题 → 关键概念 → 推理 / 关系 → 结论」串成一条连续的解释链，
最后才是需要记的结论和自测问题。本地规则引擎会按原文段落的先后顺序分步，
不会把互不相干的句子硬拼成讲解；接上模型后，步骤之间的承接关系由模型补足。

讲义仍以文字为主。只有标题或正文与欧姆定律、分组交换、TCP 三次握手**强相关**的节，才会在这一节末尾
折叠一个「辅助理解 · 可选」动画，默认不加载；弱相关不挂动画，同一章里靠正文兜底命中的同一个动画也不会反复出现。

问答区每条回答下面有三个入口：

- **图解一下**：把当前问题整理成一张有先后顺序的流程图。接模型时由模型根据这一节原文生成，
  本地规则引擎则从本节讲义或原文里抽步骤；两种来源都会标注，不会把本地整理说成模型图解。
- **B 站找课**：把问题里的疑问词去掉，保留关键词，打开 B 站课程搜索。
- **小红书搜笔记**：把同一个关键词句自动填进小红书搜索框，打开学习笔记搜索。

搜索词由确定性的词法整理生成（去掉「什么是 / 怎么 / 为什么」等疑问词，必要时补上本节标题），
不是模型总结，也不会声称是 AI 概括。

**扫描版教材**

没有文字层、或文字层是乱码时，服务端会用 Windows 自带的 OCR 在本机识别，优先读前几页的目录，
再按小节懒加载正文。需要系统安装中文 OCR 语言包（设置 → 时间和语言 → 语言和区域 → 中文 →
语言选项 → 可选功能里添加「光学字符识别」）。OCR 结果会标成「本机 Windows OCR」，
公式、符号和分栏可能失真；识别不出的页面会被排除在讲义依据之外，不会拿乱码硬凑解释。
目录识别也会挑错：习题页、答案页即使有编号和数字列，也不会被当成目录；认不出目录时退回按页分段，
并在导览下方如实写明来源。

**外刊阅读**

粘贴正文或导入 `.txt` / `.md` / 带文字层的 PDF（每页重复的页眉会被去掉，只留标题和正文）→ 存进书架 → 打开进入沉浸阅读（全局侧栏收起，
只留文章自己的返回、字号、侧栏开关和「阅读模式」）→ 单击单词查释义，双击或选中句子看结构 → 选中文字可以高亮、
写批注，或在侧栏按段查看；高亮颜色可选黄 / 绿 / 蓝 / 紫，批注只加赭色下划线、不铺高亮底色，
鼠标悬停在批注词上会直接浮出批注内容；已高亮的词仍然可以直接点击查释义，批注入口会留在查词卡上 →
点「阅读模式」会收起右侧面板，并暂停选词、查词、高亮、批注和加生词本，只保留正文阅读与批注悬停，
再点一次恢复 → 释义卡还会给出常见搭配、派生词和衍生词；例句要求模型另写真实场景里的常见用法，
与原文重合的句子会被过滤掉，不再把文章原句当例句；第一次没给全派生词或例句时，会再补问一次模型 →
生词本卡片会完整显示释义、例句、派生词和衍生词 → 点「加入生词本」，
同一个词再次加入只累加收录次数，这些内容也一起留在生词本里 →
右侧「文章问答」只依据这一篇的标题、选中内容和附近原文回答 → 读完后在正文最底端点「已阅读完毕」，
整篇会记为已读，书架显示「已读完」，也可以随时撤销；读完标记和阅读位置分开保存 →
右侧「题目」面板可以把复制来的选择题整段粘贴进去，本地自动拆成题干、选项、答案和解析，
变成可以直接点的练习；选错会同时标出所选项和正确答案，选完显示解析，选择会保存，
重新打开还在；没有提供答案的题目也能练，但会明确说明不判对错 →
字号与阅读位置自动保存，下次打开回到上次的位置。

词汇释义和文章问答都通过现有 AI 引擎生成，卡片上会写明是哪个引擎（本机 Ollama / 远程模型）。
在「设置与数据 → 词典来源」里填了牛津词典 App ID / App Key 后，查词会优先采用牛津的英文释义和官方例句，
并标成「牛津词典」；中文解释、搭配和语境含义仍由模型补充。没有配置时，卡片会明确写
「不是牛津 / 朗文等词典的官方释义」。无论是否配置，查词卡和生词本都提供跳到牛津 / 欧路词典网页的链接；
欧路没有公开的词典内容接口，所以只跳转、不抓取它的释义。本地规则引擎没有释义能力，会直接说明并引导去设置里接模型，
不会用固定模板冒充词典。AI 只能读这一篇的上下文，不会创建待办，也不会修改文章、高亮或生词本；
当前文章不会自动写进长期 AI 记忆。开启牛津词典后，查词只把选中的词发给牛津接口，不发送文章段落或生词本。
选择题的解析和保存在本机完成，不会把题目发给任何模型；重新导入会替换整组题和之前的选择记录。
当前版本不做扫描 PDF 的 OCR：提取不到文字的文件会明确提示，不会导入一个空壳。错题复习留到以后。

远程模型查词慢，通常慢在模型本身而不是网络：带思考过程的模型（例如 `Qwen3.8-27B`）即使关闭思考，
一次完整查词也可能接近一分钟；同一个接口下 `Qwen3.8-Flash-Next` 这类 Flash 模型通常十几秒。
查词请求会主动传 `reasoning_effort: "none"` 关闭思考，接口不认识这个参数时会自动去掉再重试一次；
等待面板会显示已经等了多少秒，超过 90 秒会明确报超时，不会一直转圈。
`server/llm.js` 的超时覆盖到响应体读取完成，模型先回响应头、正文却卡住的情况也会被中止。

**AI 辅助拆解**

工作台或 AI 整理空间输入 → AI 回应并给出可编辑的梳理卡 →（必要时问一个关键问题）→ 给出行动方案 →
你修改、勾选其中几条 → 确认创建 → 才真正进入待办。

## PRD 里几条最容易做歪的约束，是怎么落地的

**1. AI 建议 ≠ 正式任务。**
建议行动存在 `conversation.proposals[].actions[]` 里，只有 `POST .../confirm` 才创建 `Task`。
未确认前，待办列表里查不到它们 —— 自测里有专门的断言。

**2. 重复确认不会重复创建。**
每条建议行动有稳定 `id`；创建后写入 `createdTaskId`。
再次确认时：先看 `createdTaskId` 指向的任务还在不在，再用「同方案 + 同标题」兜一层，
两层都命中就跳过并如实告诉你「这一条已经创建过了」。

**3. 只针对用户已经确定的科目规划。**
「专业课还没定」里提到了专业课，但它不是已确定的科目。
`extractSlots()` 按分句判断否定语境，把「已确定」和「还没定」分开：
已确定的才生成任务，还没定的只进方案的 `pendingItems`（界面上叫「还没确定，所以先不安排」）。

**4. 不重复问同一个问题，且记得自己在上一轮问了什么。**
`conversation.asked` 记录问过的话题，`conversation.pendingIntent` 记住「正在等用户回答」。
所以用户只回一句「数学一和英语一」时，AI 不会把它当成新的闲聊，而是接着上一轮的规划意图走。

**5. 只想倾诉时不强行给计划。**
意图是「倾诉」时直接不生成 proposal，只回应，并留一句「想拆成小任务就跟我说」。

**6. 模拟引擎绝不冒充真实模型。**
每条 AI 消息都带 `provider: 'mock' | 'real'`，界面上分别显示「模拟引擎」或「真实模型」标签。
默认是 mock，不联网。设置页明确写了切到真实模型后你的话会被发送到那个服务。

**7. 原始记录和 AI 整理分开。**
我的档案暂时收起，但数据层仍保持着原来的边界：档案的 `content` 是用户保存的摘要，
`sourceConversationId` 只是指回来源；改摘要不会动对话，删对话也不会动档案（反之亦然）。

**8. 未实现的功能不装成能用。**
界面里只放已经能用的入口，不拿「规划中」的按钮占位置。扫描版 PDF 已支持本机 OCR，
但会明确标注哪些文字来自 OCR、哪些页面没有识别出来，不会把 OCR 结果冒充成原文。

**9. 番茄钟只在真正结束时留下记录，统计不因重开页面清零。**
放弃的一轮不写记录、不动待办；自动勾选发生在服务端，并记下任务原来的状态，
撤销时按原状态还原。结束请求带客户端令牌，断网重试不会记成两次。
每天的时长和内容拆分由服务端按本地日历日聚合，数据在 `data/focus-sessions/`，
刷新、关浏览器、隔天再打开都还在；界面不显示连续打卡和排名。

**10. PDF 原文不整本外传。**
文字提取在浏览器里完成，扫描版 OCR 在本机完成；章节框架由本地规则整理；
只有打开某一节时，才把这一节的相关文字送给所选的引擎。远程模型的数据流向在导入页、设置页和
每一节的引擎标记里都写清楚了。

**11. 外刊释义来源可核对，文章问答不越界。**
词汇卡片会写明释义来源：配置了牛津词典 API 时，英文释义和例句标成「牛津词典」；
否则标成生成它的引擎，并说明「不是牛津 / 朗文官方释义」，同时提供牛津 / 欧路词典的核对链接。
本地规则引擎没有释义能力时返回明确的 409，不用固定模板补一个假释义。
文章问答只读这一篇的标题、选中内容和附近原文，不翻出其他学习记录，不创建待办，
也不修改文章、高亮或生词本。文章正文随删除文章一起清掉；加入生词本的词按用户意愿保留。

## 第一版数据是怎么处理的

第一版（焦虑记录 → 思考档案 → 回看）里你已经写下的记录，**一条都没有丢**：

- `data/entries/` 里的原始文件**保持原样，只读，从不修改**
- 启动时自动迁移成「我的档案」里的 `thought` 档案，用 `legacyEntryId` 指回原记录
- 迁移正文里把「原始记录」和「当时整理的内容」分开，标得清清楚楚

**迁移是逐条自愈的**，不是「跑过一次就永久跳过」：

| 情况 | 行为 |
|---|---|
| 原始记录在、档案没了 | 重新补一份 |
| 档案还在 | 跳过 |
| 你在界面上主动删过这份档案 | 记进 `meta.dismissedLegacyIds`，不再复活 |

这个改动是踩出来的：早先只在 `meta.json` 记一个「已迁移」标记，结果迁移出来的档案
一旦被删掉（哪怕是测试脚本清理出错），原始记录还在却再也回不到档案里。
现在补回来过，并且不会再因为误删永久丢失。

### 教材数据的两次就地升级

已有的教材不需要重新导入。启动时会各跑一次，标记记在 `data/meta.json`：

| 迁移 | 做什么 | 为什么 |
|---|---|---|
| `textbook-demos-v2` | 按新规则重算每一节的动画；标题强匹配优先，正文兜底要多个明确信号，同章弱匹配去重 | 旧逻辑按章标题匹配，导致一本书里几乎每节都挂着同一个动画 |
| `textbook-lessons-text-first-v1` | 本地规则讲义重新生成；远程模型讲义去掉「先看动画」这类建议 | 动画只辅助理解，讲义必须以文字和原文为主 |

原文、页数、章节框架、已读进度和问答都不动；这两次迁移只更新动画标记与讲义正文。

旧的那套「思考习惯自动归纳」是**故意没有搬过来**的：
PRD 2.5 明确写了「V1.0 不自动生成未经用户确认的个人心理画像」，
原来那一页会自动生成画像，与这条冲突，所以按新文档删掉了。

## AI 整理空间为什么不「像填表」

第一版做成「输入一句 → 吐一张镶边的卡」，反馈是：不像聊天、不舒缓、太模板。
这一版按下面几条改的：

- **AI 的话不带气泡、不带边框** —— 就是一段话。一段一个气泡，
  一段回复会被拆成几条，读起来像连着说了几句
- **「问题梳理」收起来** —— 变成一个可以点开的小标题，只有你点开才展开；
  里面每条仍然能直接改、能删
- **「建议」长在对话里** —— 一行一句，没有底色没有框，label 写的是
  「我建议可以试试这几步」，不再是「方案卡」
- **不用下指令** —— 不需要说「帮我拆成小任务」。只要这一轮聊到了能落地的事，
  AI 会直接说「我建议你可以先从很小的一步开始：…」，然后由你确认
- **每条回复后面有快捷回话** —— 「好，加进待办」「只想先做第一条」「这次先不用」，
  让对话能接下去，而不是问一句就断了
- **输入框 Enter 发送、Shift+Enter 换行**，正在输入显示三个跳动的点
- **先接住情绪再谈事情** —— 回复的第一段永远是承接，第二段才说事

产品约束照旧：梳理内容只呈现真正需要的栏目；建议必须你确认才创建任务；
可只选部分；重复确认不重复创建；只想倾诉时不推计划。

## 数据在哪

```
data/
  tasks/            任务，一个任务一个 JSON 文件
  plans/            学习计划
  projects/         学习项目与它下面的课程、进度（一个项目一个 JSON 文件）
  conversations/    对话、消息、行动方案（都在一个文件里）
  archives/         我的档案
  entries/          第一版的原始记录（只读保留）
  focus-sessions/   已完成的专注记录（含实际秒数、是否自动勾选；按本地日历日聚合展示）
  focus-active.json 正在进行的那一轮（网页与桌面浮窗共用；结束后删除）
  focus-aliases.json 专注内容的归类关系（只做统计合并，不改原始记录）
  textbooks/        教材元数据、章节框架、讲义、问答、提取的逐页文字与原始 PDF
  articles/         外刊元数据、高亮批注与阅读进度（一个文章一个 JSON 文件）
    content/        正文段落，单独存放，列表接口不读这一层
    chats/          每篇文章自己的 AI 对话
  vocabulary/       生词本（同一个词合并收录次数；含释义、例句、搭配、派生词、衍生词与词典来源）
  settings.json     AI 引擎设置（含 API Key，注意别外传）
  meta.json         迁移标记
  .float-runtime/   浮窗的窗口位置、吸边偏好与 Electron 缓存（可随时删，删了只是回到默认）
```

写入用的是「临时文件 + 改名」的原子替换，写到一半出错不会把已有记录写坏。
单个 JSON 文件损坏也只会被跳过，不会让整站打不开。

**备份**：设置页可以导出
- `导出任务、对话与档案（JSON）` — 这几类数据的完整备份，**不含 API Key**（含学习项目）
- `导出任务、对话与档案（Markdown）` — 人能直接读，含计划、学习项目、任务、档案、完整对话

专注记录、教材数据和外刊数据目前**不在**这两个导出文件里；需要完整备份时，请一并复制
`data/focus-sessions/`、`data/textbooks/`、`data/articles/` 和 `data/vocabulary/`。
设置页也写了这句话，避免把部分备份误当成「全部」。

### 学习项目接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` / `POST` | `/api/projects` | 项目列表 / 新建项目 |
| `GET` / `PATCH` / `DELETE` | `/api/projects/:id` | 项目详情 / 编辑 / 删除 |
| `GET` / `POST` | `/api/projects/:id/courses` | 课程列表 / 添加课程 |
| `GET` / `PATCH` / `DELETE` | `/api/projects/:id/courses/:courseId` | 课程详情 / 编辑进度 / 删除课程 |
| `POST` | `/api/projects/:id/courses/:courseId/continue` | 计算并打开「继续学习」的目标集数 |
| `POST` | `/api/projects/:id/courses/:courseId/complete` | 确认完成当前这一集 |

### AI 学习上下文接口（阶段 1，只读）

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/conversations/:id/context` | 预览当前选择会引用哪些真实记录；可用查询参数临时覆盖选择 |
| `PATCH` | `/api/conversations/:id` | 保存学习数据选择（项目 / 7 或 30 天 / 待办） |

上下文只汇总用户明确选择的白名单字段，有数量上限，不返回整个数据库。
知识点、错题和复习进度目前没有数据模型，接口会明确标注为不可用。
这一阶段只做选择和预览，还没有接到 AI 引擎，也不会把数据发送到远程服务。

几条固定规则：

- **两个集数分开**：`lastEpisode` 是最近正在看的集数，`completedEpisodes` 是从第 1 集开始的连续完成数。
- **继续学习**会先算出实际目标集数，再写回 `lastEpisode` 与 `lastStudiedAt`；学到一半时打开的是当前这集，不是下一集。
- **顺序学习**：`complete` 只接受「已完成集数 + 1」的那一集。跳集时返回 `409` 并说明原因，绝不推断中间集数已完成。
- **项目进度按集数加权**：只统计填写了总集数的课程（Σ 已完成 / Σ 总集数）；全部未填时返回 `percent: null`。
- **B 站链接**：只有 `/video/` 链接本身已经带 `p` 参数时才改写集数；其余情况原样返回保存的链接。
- **删除只解除关联**：删项目会连同课程一起删，但关联任务只清空 `projectId` / `courseId`，任务本身保留。

### 外刊阅读接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` / `POST` | `/api/articles` | 文章列表（不含正文）/ 新建文章 |
| `GET` / `PATCH` / `DELETE` | `/api/articles/:id` | 详情（含段落）/ 编辑元数据、字号 / 删除文章及其正文与对话 |
| `PUT` | `/api/articles/:id/content` | 替换正文；旧高亮、阅读位置、读完标记和选择题会一起清空 |
| `PATCH` | `/api/articles/:id/progress` | 保存阅读位置（段号 + 段内比例），百分比由服务端计算 |
| `POST` / `DELETE` | `/api/articles/:id/finish` | 标记整篇已读完 / 撤销标记 |
| `PATCH` | `/api/articles/:id/quiz` | 替换整组选择题，或按 `questionId` 保存某题的选择 |
| `DELETE` | `/api/articles/:id/quiz` | 清空这篇文章的选择题和自己的选择记录 |
| `POST` | `/api/articles/:id/highlights` | 新增高亮 / 批注（字符偏移 + 颜色） |
| `PATCH` / `DELETE` | `/api/articles/:id/highlights/:highlightId` | 修改批注、颜色或范围 / 删除高亮 |
| `POST` | `/api/articles/:id/lookup` | 用当前文章上下文解释选中的词、短语或句子 |
| `GET` / `POST` / `DELETE` | `/api/articles/:id/chat` | 读取 / 发送 / 清空这篇文章的 AI 对话 |
| `GET` / `POST` | `/api/vocabulary` | 生词本列表 / 加入生词（同词合并，累加次数） |
| `GET` / `PATCH` / `DELETE` | `/api/vocabulary/:id` | 生词详情 / 备注 / 删除 |

`lookup` 和文章 `chat` 都走现有 AI 引擎：`mock` 没有释义能力时返回 `409 ai-unavailable`，
不会伪造词条；`real` 和 `ollama` 的失败会带着可读原因返回。文章正文、段落和高亮都进不了
其他页面或长期 AI 记忆，只有这次请求明确选中的文字会进入上下文。
词典来源是可选的：在 `PATCH /api/settings` 里保存 `oxfordAppId` / `oxfordAppKey` 后，
查词只把选中的词发给牛津接口；接口包装成 `dictionarySource: "oxford"` 和 `oxford` 字段返回，
App Key 不会出现在任何返回值或导出文件里。欧路没有公开的词典内容接口，只返回网页链接，不抓取内容。

`uitest.js` 用一个最小 DOM 桩在 Node 里把主要视图真正渲染一遍，

外刊书架、生词本、阅读器四栏与高亮渲染、四种高亮颜色与未知颜色回退、
批注只用赭色下划线、不铺高亮底色、悬停批注词浮出批注内容、移开即收起、

重叠高亮取最后一条颜色、批注卡片显示颜色与批注标记、
高亮词点击仍走查词、生词卡上的派生词、衍生词、例句与牛津词典来源、
选择题的粘贴解析（含全角数字与选项、答案和解析）、空状态导入入口、题目数量与选择状态、
选错 / 选对标记、无答案提示、选择保存与刷新后仍在，
mock 引擎的诚实提示、字号与进度控件、PDF 每页重复的页眉会被清掉而正文开头的共同措辞不会被误删；
此外静态检查浮窗页面：独立于主站外壳、能勾待办、每条待办可自定义时长、
能勾选与暂停/放弃、吸边悬浮球有倒计时、不使用 `innerHTML`、桌面外壳透明置顶且隔离 Node。
它不保证 CSS 的实际观感 —— 那需要真人打开看。

Ollama 相关的行为不进自动化（它会真调本机模型、耗时不确定），
所以是手动验证的：`/api/ai/status` 探测、模型列表、切换引擎、回复里的引擎标注与回退。

> ⚠️ **自测会写入并清理测试数据。** 它只删除自己创建的东西（启动时记录快照，结束时对比），
> 但如果你**同时在用这个应用新建任务**，理论上可能撞上竞态。
> 所以建议在不用的时候跑，或者先导出一份备份。
> 你真实的数据（任务、计划、对话、档案）在正常使用中不会被自测碰到。
