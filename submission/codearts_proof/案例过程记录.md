# 码道应用过程记录

对应说明文档第四章的三个案例。每条按同一顺序记：**我给的约束 → AI 给的方案 → 被否决的版本 → 用来收口的断言/验证输出**。

## 案例一：全新数据目录启动时，并发写设置文件报 EPERM

**现象**

删掉数据目录重新启动桌面版，`GET /api/bootstrap` 返回 500，服务端日志：

```
Error: EPERM: operation not permitted, rename
  '...\data\settings.json.tmp' -> '...\data\settings.json'
```

只在「第一次启动」出现，第二次启动不复现。

**我给的约束**

1. 只改 `db.getSettings()` 的落盘时机，不许动任何调用方；
2. 不许引入锁文件、不许加 `setTimeout` 重试；
3. 不许改变 `settings.json` 的磁盘格式（老用户的文件要能直接读）。

**AI 给的方案**

`getSettings()` 每次调用都会走一遍「迁移旧配置 → 写 `.tmp` → rename」，而桌面版启动时主进程和 Node 子进程几乎同时调用它，两个进程写同一个 `.tmp`，rename 撞车。改法：迁移只在内存里做，落盘挪到 `ensureDirs()` 里，进程启动时串行执行一次。

**被否决的版本**

- 全局 mutex + 失败重试 3 次：能压住报错，但把「重复落盘」这个真问题藏起来了；
- 每个进程用不同 `.tmp` 文件名：能过，但会留下垃圾文件，且 `db.js` 的「唯一持久化入口」这条约束被破坏。

**收口**

- 删数据目录重建，连开 5 次，`/api/bootstrap` 全部 200；
- `server/selftest.js` 里补一条「新目录启动后 settings.json 只被创建一次」的断言；
- 全量回归：接口自测 388 项全绿。

## 案例二：批量删除对话返回 500（SAFE_DELETE_BULK_CONFIRM_REQUIRED）

**现象**

前端批量删除 2 个以上对话，直接 500，界面上只有一句「操作失败」。

**我给的约束**

1. 不许把内部错误码原文透给用户；
2. 删掉的东西要能找回——这是产品承诺，不是可选项；
3. 前端不加「你真的要删吗」以外的二次确认。

**AI 给的方案**

两个问题叠在一起：① `fsp.rm(path, {recursive:true})` 是真删，与「删除是软删除」的产品约定冲突；② 抛出的 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 属于内部保护码，被当成 5xx 原文返回。改法：`fsp.rm` 换成 `moveToTrash()`，文件挪进 `data/.trash/`；5xx 响应统一脱敏，只回「操作没有完成」。

**被否决的版本**

- 前端加弹窗、要求输入「删除」二字：治标，文件仍然被真删，误删照样找不回；
- 把保护码直接透给用户并提示「请带 confirm 参数重试」：把内部契约暴露成用户文案。

**收口**

- 自测里加一条反向断言：**删除之后原文件仍然在 `.trash/` 里**；
- 这条断言后来成了重构时的护栏——任何时候有人把软删除改回真删，测试立刻红。

## 案例三：桌面版点「浮到桌面」却提示要先装 Electron

**现象**

已经装好的 exe（Electron 架构），点「浮到桌面」弹出一句：

> 请先 `npm install --save-dev electron`

**我给的约束**

1. 不许让用户为了浮窗再装任何东西；
2. 不许起第二个 Electron 进程（内存翻倍，且单实例锁会打架）；
3. 网页版原有的浮窗行为不能退化。

**AI 的定位（三条原因叠在一起）**

1. 判定逻辑去找 `node_modules/electron`，打包后这个目录根本不存在，于是判定为「没装 Electron」；
2. `electron-builder.yml` 的打包清单只写了 `desktop/main.js`，`float-main.js`、`preload.js` 压根没进包；
3. 就算前两条都过了，`spawn` 自己的 `process.execPath` 也只会再开一个主窗口——Electron 的单实例锁会把新进程当成第二次启动。

**AI 给的方案**

浮窗逻辑抽成 `desktop/float-window.js`，由主进程在**同一个 Electron 进程**里开第二个 `BrowserWindow`（透明、无边框、置顶、吸边成小球）；主进程再开一条只监听 `127.0.0.1` 的随机端口 HTTP 通道，带一次性令牌，通过环境变量 `WB_DESKTOP_SHELL_URL` / `WB_DESKTOP_SHELL_TOKEN` 交给服务子进程。服务端 `launchFloatWindow()` 有这条通道就走进程内开窗，没有才回退到 `spawn`（网页版 + 本机 Electron 的旧路径）。

**被否决的版本**

- 继续 `spawn` 子进程跑 `float-main.js`：打包后路径找不到，且两个 Electron 抢单实例锁；
- 把 Electron 打进 asar 再去 `require.resolve`：治了第 1 条，第 3 条照样过不去；
- 用第三方面板库重写浮窗：引入依赖，且网页版行为会跟着变。

**收口**

- 开发态日志三段可复现：`已新开窗口` → `页面已加载` → `叫回已有窗口`；
- `uitest.js` 里补三条断言：外壳透明/无边框/置顶、`contextIsolation` 开且 `nodeIntegration` 关、能把窗口收成小球并拖回；
- 打包版冒烟脚本 `scripts/desktop-smoke.js` 4/4 通过，浮窗项返回「进程内开窗」。

## 其它排错记录（同一套方法）

| 问题 | 约束 | 结果 |
|---|---|---|
| APK 171 MB，超过分发上限 | 不许砍功能，不许去掉 WebView 的调试能力 | `useLegacyPackaging true` 压缩 `libnode.so`，再按 ABI 分包，最终 arm 包 65 MB |
| libnode 下载超时 / 代理 502 | 不许跳过校验直接解压 | 换镜像下载，SHA256 校验通过后放进 Gradle 缓存，构建脚本里保留校验步骤 |
| `npm i` 被环境的删除保护钩子拦截 | 不许改全局配置 | 安装前清掉 `NODE_OPTIONS`，依赖落到项目内 `.npm-cache` |
| Electron 被 `ELECTRON_RUN_AS_NODE=1` 影响，起不来 | — | 启动脚本里显式 `unset ELECTRON_RUN_AS_NODE`，写进 `desktop-smoke.js` 的说明 |

## 一套固定顺序（三个案例都走这个）

```
写清约束（要什么 / 不要什么 / 边界在哪）
      ↓
让 AI 复述一遍约束（理解偏了在这一步就能发现）
      ↓
AI 出实现（一次可以给很多文件）
      ↓
跑三套自测（接口 / AI / 前端）+ 真机或模拟器跑一遍
      ↓
跑绿才算完；不绿就带着完整堆栈回到第一步
```

第三段是决定性的。没有断言，「AI 写完了」只是一句声明。
