# 缓一缓 · 个人学术工作台

> 安排学习任务、管理长期计划；用一个能关联待办的番茄钟留出专注时间；
> 把 PDF 教材拆成章、节，逐节读讲义、看原文、向 AI 提问；
> 思绪混乱或卡住的时候可以自然地聊一聊，等你确认之后，再把有用的部分变成待办。

作品说明文档 · 对应 `readme/` 目录<br>
形态：网页版 / Windows 桌面版 / 安卓 App　｜　数据：全部留在本机，不上传

## 0. 先看这里：作品是什么

**要解决的问题。** 考研、考证、跨专业自学的人，通常同时在用四五个工具：待办清单记任务、番茄钟计时、
PDF 阅读器看教材、错题本、再开一个 AI 聊天窗口问问题。工具之间互不相通——计时不知道自己计的是哪门课，
AI 不知道你昨天读到第几节，待办里躺着一堆从没有真正开始过的条目。

**这件事做成什么样。** 「缓一缓」把四件事放进同一个本地应用，并且**只在被确认时才写数据**：

- **任务与计划**：手动就能用，完全不依赖 AI；
- **专注番茄钟**：每一轮都关联一条具体待办或一句自由目标，结束时按实际经过的时间记账；
- **教材精读**：PDF 在浏览器里提取文字与书签，拆成章/节，逐节生成讲义、随时提问；
- **外刊阅读**：查词、高亮、批注、按篇问答，生词进生词本；
- **AI 整理空间**：自然聊 → 问题梳理卡 → 行动方案卡 → 你勾选确认 → 才变成待办。

**几个刻意的选择。**

| 选择 | 原因 |
|---|---|
| 服务端零第三方依赖（只用 Node 内置模块） | 十年后还能跑；评审拿到源码不需要 `npm install` 就能启动 |
| 数据是 `data/` 下的 JSON 文件，一文件一条目 | 打开文件夹就能看懂；坏了只坏一条；备份就是复制目录 |
| AI 有三个引擎，默认规则引擎 | 没配 Key 也能完整使用，且会如实标注「这句是本地规则整理，不是模型生成」 |
| 不连接任何云服务 | 教材、对话、错题都属于个人；不需要账号，不需要联网 |

自研代码约 **3.7 万行**（服务端 1.63 万 / 前端 1.97 万 / 桌面壳 0.1 万），
自测 **765 项**（接口 388 + AI 55 + 前端 322），当前全绿。

## 1. 环境依赖说明与一键安装脚本

### 1.1 三种使用方式，按需要选一种

| 方式 | 需要什么 | 适合谁 |
|---|---|---|
| **桌面版（推荐评审用）** | Windows 10/11，无需安装任何运行时 | 想直接看完整功能的人 |
| **安卓版** | Android 8.0（API 24）及以上 | 想在手机上看的人 |
| **源码版** | Node.js ≥ 18（推荐 20 / 22 LTS） | 想看代码、想自己改的人 |

三种方式都不需要数据库、不需要账号、不需要联网（用到远程 AI 模型时才需要联网）。

### 1.2 环境依赖明细

| 依赖 | 版本 | 是否必需 | 说明 |
|---|---|---|---|
| Node.js | ≥ 18（推荐 20 / 22 LTS） | 源码版必需 | 服务端只用内置模块，**不需要 `npm install`** |
| 操作系统 | Windows 10/11 | 桌面版必需 | 浮窗、本机 OCR 依赖 Windows 能力 |
| 浏览器 | Chrome / Edge 近两年版本 | 网页版必需 | 需要 ES Module 与 `fetch` 流式响应 |
| Electron | 45.2.3 | 可选 | 只有要桌面版或浮窗才需要，已随安装包提供 |
| Android SDK + JDK 21 | — | 可选 | 只有要自己重新打 APK 才需要 |
| Ollama | 0.1.x 以上 | 可选 | 想用本机模型时安装；不装也能用规则引擎或远程模型 |

> 刻意没有引入的东西：数据库、前端框架、UI 组件库、CDN 字体、任何运行时 npm 依赖。
> 服务端 `require` 的全是 Node 内置模块，`package.json` 里也没有 `dependencies` 字段。

### 1.3 一键安装脚本（Windows）

把本目录（`readme/`）复制到项目根目录，或在项目根目录直接双击：

```
一键安装.bat
```

脚本会依次做六件事，每一步失败都会停下来中文说明原因：

1. 检查 `node` 是否存在，不存在就给出下载地址并退出；
2. 检查 Node 版本是否 ≥ 18；
3. 检查 `server/server.js` 是否在预期位置（防止只拷了部分文件）；
4. 检查并创建 `data/` 目录与 `data/settings.json`；
5. 探测 5180 端口是否被占用，被占用就自动往后找一个空闲端口；
6. 启动服务并把地址打印出来，同时在浏览器里打开。

常用参数：

```bat
一键安装.bat                 :: 默认 5180，自动开浏览器
一键安装.bat /port=5200      :: 指定端口
一键安装.bat /no-browser     :: 只起服务，不开浏览器
一键安装.bat /check          :: 只做环境检查，不启动
```

日常启动用 `启动.bat`（它等同于 `一键安装.bat /no-check`，不再重复检查环境）。

### 1.4 手动安装（三条命令）

```bash
node -v                      # 确认 ≥ 18
node server/server.js        # 启动，默认 http://127.0.0.1:5180
```

要看桌面版：`npm install --save-dev electron && npm run desktop`。

### 1.5 AI 模型由使用者自己填（只存本机）

应用**不预置任何模型、不内置任何 Key**。第一次打开是规则引擎，功能完整可用；
要接真模型，在「设置与数据 → 模型供应商」里自己加一条：

| 字段 | 示例 | 说明 |
|---|---|---|
| 名称 | 硅基流动 | 只是显示名 |
| 接口类型 | OpenAI 兼容 / Ollama | 决定调用协议 |
| Base URL | `https://api.siliconflow.cn/v1` | 到 `/v1` 为止 |
| API Key | `sk-...` | 只写进本机 `data/settings.json`，界面上只显示后四位 |
| 模型 | 拉取列表或手填 `Qwen/Qwen2.5-7B-Instruct` | 可加多个，对话里随时切 |

保存后点「测试连通」会真的发一次最小请求，把模型列表拉回来验证。
Key 不经过任何第三方服务器，也不随提交包分发。

## 2. 部署运行步骤

### 2.1 桌面版（最快看到完整功能）

1. 双击 `project/缓一缓-2.0.0-便携版.exe`（便携版，不写注册表，不用安装）；
   或运行 `project/缓一缓-2.0.0-安装版.exe` 走安装流程（可选安装目录、建快捷方式）。
2. 首次启动约 3–5 秒（要先拉起内置的本地服务）。
3. 数据落在 `%APPDATA%\huan-yihuan-desktop\data`，与网页版、安卓版完全隔离。
4. 想放桌面浮窗：待办页或专注页右上角「浮到桌面」，会开一个透明置顶小窗，可吸边成小球。

> 安装包**没有购买代码签名证书**，Windows 首次运行会提示"未知发布者"。
> 点「更多信息 → 仍要运行」即可，不是坏包。

### 2.2 安卓版

1. 把 `project/缓一缓-2.0.0-安卓版.apk` 传到手机安装（需允许"安装未知来源应用"）。
2. 首次启动等 **10–20 秒**：App 内要先拉起一个 Node 运行时再加载页面，这是正常的。
3. 数据写在 App 私有目录，卸载即清空；不联网也能用。

### 2.3 源码版

解压 `project/缓一缓-2.0.0-源码.zip`（不含 `node_modules`），在根目录直接跑：

```bash
node server/server.js                 # 网页版，http://127.0.0.1:5180
node server/server.js --open          # 起服务并自动开浏览器
npm run desktop                       # 桌面版（开发态）
npm run desktop:pack                  # 打 Windows 安装包（需要 electron-builder）
npm run mobile:apk                    # 打安卓 APK（需要 Android SDK + JDK 21）
```

一台电脑跑两份互不干扰的数据（桌面一份、手机一份）：

```bash
node scripts/start-two.js                       # 桌面 5180 / 手机 5181
node scripts/start-two.js --phone-token=你的口令  # 手机那份加访问口令
```

### 2.4 首次配置（约 3 分钟）

| 步骤 | 在哪 | 做什么 |
|---|---|---|
| 1 | 打开应用 | 直接能用，此时是规则引擎，页面会标注来源 |
| 2 | 侧栏底部 → 设置与数据 | 添加供应商，填 Base URL 与 Key |
| 3 | 同一页 → 测试连通 | 拉回模型列表，确认网络与 Key 没问题 |
| 4 | 选一个默认模型 | 之后所有对话默认用它；单条对话还能再换 |
| 5 | 想用本地模型 | 装 Ollama → 拉一个模型 → 供应商类型选 Ollama |

### 2.5 数据在哪、怎么备份

| 形态 | 位置 |
|---|---|
| 网页版 / 源码版 | 项目下的 `data/` |
| 桌面版 | `%APPDATA%\huan-yihuan-desktop\data` |
| 安卓版 | App 私有目录（`app.datadir()/data`） |

备份＝把整个 `data/` 目录复制走；恢复＝把它放回去。没有数据库，没有导出格式，
`data/` 下的 JSON 用记事本就能读。教材 PDF 原文存在 `data/textbooks/` 下。

### 2.6 常见问题

| 现象 | 原因与处理 |
|---|---|
| 提示端口被占用 | 换端口：`一键安装.bat /port=5200`，或关掉占用 5180 的进程 |
| 双击 bat 闪退 / 「不是内部或外部命令」 | 没装 Node，或安装后没重开命令行窗口 |
| 桌面版提示"未知发布者" | 未买代码签名证书，属正常，点「仍要运行」 |
| 安卓版第一次打开白屏十几秒 | App 内 Node 正在启动，等一会即好；一直白屏请检查是否被系统省电策略限制 |
| 浮窗点不出来（网页版） | 网页版没有桌面外壳，需装一次 Electron，或直接用桌面版 |
| AI 回答是"本地规则整理" | 还没配模型，属预期行为；配好模型后会自动切换并标注引擎 |
| 扫描版教材识别出错 | 需要 Windows 中文 OCR 语言包；公式与多栏排版会失真，属已知限制 |

## 4. 码道在项目开发中的应用总结

### 4.1 总原则：先给约束，再让 AI 写；用测试收口

这个项目从第一行代码起就是 AI 辅助开发的，但用法不是"描述需求 → 收代码"，而是三段式：

```
我写约束（PRD 条款 / 边界条件 / 不许做什么）
      ↓
AI 出实现（可以一次给很多文件）
      ↓
我用自测断言验证（写完就跑，跑绿才算完）
```

关键在于第三段。项目里有 765 条自测断言，其中相当一部分是"不许做什么"的反向断言，例如：

- 欢迎区不许出现任何催促文案；
- 本地规则引擎整理的内容，不许被标成"模型生成"；
- AI 不许在用户没确认时直接建待办；
- 删对话不许真删文件（要进回收站）。

这些断言一旦写进 `selftest.js` / `uitest.js`，AI 后面再怎么重构都绕不过去。

### 4.2 三类典型用法

| 用法 | 具体怎么做 | 效果 |
|---|---|---|
| **架构落地** | 先把分层写死（`server.js` 只做校验与编排、`db.js` 是唯一持久化入口、`models.js` 管字段），再让 AI 往骨架里填 | 3.7 万行代码没有出现"到处直接读文件"的腐烂 |
| **增量重构** | 每次只改一个明确边界，改完立刻跑三套自测 | 一次能改动十几个文件而不破坏已有行为 |
| **排错** | 带着**完整报错栈 + 复现条件 + 已排除的可能**去问，而不是"报错了帮我看看" | 下面三个案例都是一轮内定位 |

### 4.3 三个真实案例

**案例一：全新数据目录启动时，并发写设置文件报 EPERM**

- 现象：桌面版第一次启动，服务端返回 500，日志里是 Windows `EPERM`（文件被占用）。
- 我给的约束：只改 `db.getSettings()` 的落盘时机，不许动调用方；不许引入锁文件。
- 定位过程：AI 指出 `getSettings()` 每次调用都会"迁移旧配置 → 写临时文件 → rename"，
  而桌面版启动时主进程和子进程几乎同时调用它，两个临时文件撞在一起。
- 修法：迁移只在内存里做，落盘挪到 `ensureDirs()` 里串行执行一次。
- 验证：删掉数据目录重建，连开 5 次不再报错。

**案例二：删除对话返回 500（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`）**

- 现象：批量删对话直接 500，前端只显示"操作失败"。
- 我给的约束：不许把内部错误码透给用户；删掉的东西要能找回。
- 修法：`fsp.rm` 换成 `moveToTrash()`，文件挪进 `data/.trash/`；5xx 响应做脱敏。
- 验证：自测里加了一条"删除后原文件仍在 .trash 里"的断言。

**案例三：桌面版"浮到桌面"提示要装 Electron（已装桌面版却仍提示）**

- 现象：装好的 exe 里点浮窗，弹出"请先 `npm install --save-dev electron`"。
- 我给的约束：不许让用户为浮窗再装任何东西；不许起第二个 Electron 进程（内存翻倍）。
- 定位过程：三个原因叠在一起——① 判定逻辑去找 `node_modules/electron`，打包后不存在；
  ② 打包清单只写了 `desktop/main.js`，浮窗文件根本没进包；③ 就算找到，spawn 自己的 exe
  也只会再开一个主窗口。
- 修法：把浮窗逻辑抽成 `desktop/float-window.js`，由主进程在**同一个 Electron** 里开第二个窗口；
  主进程开一条只监听 `127.0.0.1`、带一次性令牌的内部控制通道给服务端用。
- 验证：开发态日志三步（已新开窗口 → 页面已加载 → 第二次叫回已有窗口）；
  打包版冒烟 4/4 通过，浮窗项返回「进程内开窗」。

### 4.4 沉淀下来的五条方法

1. **把"不要什么"写进测试**，比写"要什么"更能约束 AI 的行为边界。
2. **报错要给全**：完整堆栈 + 复现步骤 + 已排除项，比反复描述现象省三轮。
3. **一次只放开一个边界**：改数据层就不顺手改界面，否则测试挂了不知道是谁的锅。
4. **让 AI 先复述约束再动手**：理解偏了在第一步就能发现，而不是在第十个文件之后。
5. **文档与代码同源**：README 里的每条约束都能在自测里找到对应断言，避免"文档说得好、代码没做"。

### 4.5 明确没有交给 AI 的部分

- **产品判断**：哪些功能进 V1、哪些砍掉（章节知识图谱、错题整理都砍了），由人定；
- **视觉方向**：纸页/书房这套低饱和、无排行榜、无打卡的调性，是人工反复调出来的；
- **数据取舍**：首版记录怎么迁移、哪些字段能删哪些只能加墓碑，人工决策；
- **最终验收**：所有外发产物（exe、APK）都在真机/模拟器上跑过一遍才留。
